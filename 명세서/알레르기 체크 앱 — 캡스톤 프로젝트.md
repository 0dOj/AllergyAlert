# 알레르기 체크 앱 — 캡스톤 프로젝트

바코드를 스캔해 식약처 공공데이터에서 원재료를 조회하고, 등록한 알레르기 유발물질 포함 여부를 판정하는 서비스.

## 1. 핵심 흐름

| 단계 | 입력 | 처리 | 출력 |
| --- | --- | --- | --- |
| ① | 바코드 | C005 바코드연계제품정보 (`BAR_CD`) | 품목보고번호 · 제품명 |
| ② | 품목보고번호 | C002 품목제조보고 원재료 (`PRDLST_REPORT_NO`) | 원재료 문자열 (`RAWMTRL_NM`) |
| ③ | 원재료 문자열 | 알레르겐 매칭 (동의어 사전 + 오탐 제외) | 위험 / 주의 / 안전 |
| ④ | 판정 결과 | 결과 화면 | “경고: 땅콩 성분이 포함되어 있습니다” |

## 2. API 검증 결과 (2026-09-19 실측)

### 서비스별 데이터 규모

| 서비스 ID | 이름 | 건수 | 상태 |
| --- | --- | --- | --- |
| C005 | 바코드연계제품정보 | 259,681 | 활용신청 완료 |
| I2570 | 유통바코드 | 53,245 | 활용신청 완료 |
| C002 | 식품(첨가물)품목제조보고(원재료) | 1,074,854 | 활용신청 완료 |
| I1250 | 식품(첨가물)품목제조보고 | — | 미신청 (INFO-110) |

**1단계는 C005를 쓸 것.** I2570보다 바코드 커버리지가 약 5배 넓다.

### end-to-end 성공률

C005에서 무작위 15건을 뽑아 C002 조인을 시도한 결과 **7건 성공 / 8건 실패 (약 47%)**.

실패 유형:

- **포장육·수입식품** — 식품 품목제조보고 대상이 아니라 C002에 구조적으로 없음 (예: 통오리, 그뤼에르치즈)
- **생산중단·폐업 제품** — 보고가 정리되어 조회 불가 (예: 옹심이 고기만두, 팥찐빵, 갈비산적)

실제 앱 성공률 = 바코드 커버리지 × 조인율. 바코드 데이터는 2018년 이후 갱신이 중단되어 최신 제품은 조회되지 않는다.

### 운영 제약

- **09:00~19:00 (KST) 서비스 차단** — `ERROR-503`. 단, 2026-09-19(토) 12:16에는 정상 응답했으므로 **주말에는 미적용**으로 보임
- 증분 파라미터 없이 **시간당 100회**
- 1회 요청 최대 1,000건
- 파일 다운로드 인증키당 서비스별 **1일 10회**
- 동시 요청을 많이 보내면 응답이 비는 현상 확인 → 순차 호출 권장

## 3. API 명세 (검증 완료)

### 공통

- **Base** — `http://openapi.foodsafetykorea.go.kr/api`
- **형식** — `/{인증키}/{서비스ID}/{json|xml}/{startIdx}/{endIdx}/{변수명}={값}`
- **파일 덤프** — `/{인증키}/{서비스ID}/file`

쿼리스트링이 아니라 **경로에 `변수명=값`을 붙이는 방식**. 인자 2개 이상은 `/A=1&B=2`.

### 응답 코드

| 코드 | 의미 |
| --- | --- |
| INFO-000 | 정상 |
| INFO-200 | 해당 데이터 없음 |
| INFO-110 | 서비스 활용신청 내역 없음 |
| ERROR-503 | 09~19시 서비스 제한 |
| ERROR-310 | 잘못된 서비스 ID |

### C005 — 바코드연계제품정보

- 인자: `BAR_CD`, `PRDLST_REPORT_NO`, `CHNG_DT`
- 출력: `PRDLST_REPORT_NO`, `PRDLST_NM`(제품명), `BSSH_NM`(제조사), `PRDLST_DCNM`(식품유형), `POG_DAYCNT`(소비기한), `END_DT`(생산중단일), `CLSBIZ_DT`(폐업일), `INDUTY_NM`, `SITE_ADDR`, `BAR_CD`

### I2570 — 유통바코드

- 인자: `BRCD_NO` ← **`BAR_CD`가 아님. 서비스마다 다르니 주의**
- 출력: `BRCD_NO`, `PRDLST_REPORT_NO`, `PRDT_NM`, `CMPNY_NM`, `PRDLST_NM`/`HRNK_PRDLST_NM`/`HTRK_PRDLST_NM`(소/중/대분류)

### C002 — 품목제조보고(원재료)

- 인자: `PRDLST_REPORT_NO`, `PRDLST_NM`, `BSSH_NM`, `LCNS_NO`, `RAWMTRL_NM`, `PRMS_DT`, `PRDLST_DCNM`, `CHNG_DT`
- 출력: `RAWMTRL_NM`(원재료명), `RAWMTRL_ORDNO`(표시순서), `PRDLST_NM`, `PRDLST_DCNM`, `BSSH_NM`, `PRMS_DT`, `LCNS_NO`, `CHNG_DT`, `ETQTY_XPORT_PRDLST_YN`

**응답 형태 확인됨** — 원재료가 row별로 쪼개지지 않고 **한 row에 쉼표로 이어붙어** 온다. `RAWMTRL_ORDNO`는 `"7,8,9,10,11,12"` 같은 형태.

실제 응답 예시:

```json
{
  "PRDLST_NM": "가시오가피 냉면",
  "BSSH_NM": "주식회사 금성에프앤비",
  "PRDLST_DCNM": "숙면",
  "RAWMTRL_NM": "밀가루, 정제수, 타피오카전분, 가시오갈피분말, 알카리제, 정제염",
  "RAWMTRL_ORDNO": "7,8,9,10,11,12"
}
```

## 4. 아키텍처 원칙

> 앱 런타임에서 식약처 API를 직접 호출하지 말 것. 09~19시 차단과 시간당 100회 제한 때문에 낮 시연이 불가능해진다.
> 

| 계층 | 흐름 | 실행 시점 |
| --- | --- | --- |
| 야간 배치 | 식약처 OpenAPI → 로컬 DB 적재 | 전체 덤프 1회 → 이후 `CHNG_DT` 증분 |
| 앱 런타임 | 바코드 → 로컬 DB 조회 → 알레르기 매칭 → 결과 | 사용자 요청 시 (외부 API 호출 없음) |

수집(ingest)과 조회(serve)를 완전히 분리한다.

### 3단 폴백

1. 바코드 → C005
2. 바코드 → I2570
3. 제품명 검색 → C002 `PRDLST_NM` (107만 건이라 훨씬 잘 걸림)

미조회는 **에러가 아니라 정상 분기**로 설계한다.

## 5. 알레르기 매칭 설계

대상: 식약처 표시대상 19개 항목 (조개류의 굴·전복·홍합을 따로 세어 통상 22종)

알류(가금류) · 우유 · 메밀 · 땅콩 · 대두 · 밀 · 고등어 · 게 · 새우 · 돼지고기 · 복숭아 · 토마토 · 아황산류 · 호두 · 닭고기 · 쇠고기 · 오징어 · 조개류(굴·전복·홍합) · 잣

### 동의어 사전이 필요한 이유

공개 데이터에는 **포장재의 알레르기 표시란에 해당하는 항목이 없다.** C002가 주는 건 원재료명 원문(`RAWMTRL_NM`)뿐이므로, 알레르겐을 문자열에서 역추론해야 한다.

| 알레르겐 | 동의어 예시 |
| --- | --- |
| 우유 | 유청, 유청분말, 탈지분유, 전지분유, 유당, 버터, 치즈, 카제인, 유크림, 연유 |
| 대두 | 콩, 된장, 간장, 두부, 분리대두단백, 대두유, 대두레시틴 |
| 밀 | 소맥, 소맥분, 밀가루, 글루텐, 밀전분, 강력분 |
| 알류 | 계란, 달걀, 난백, 난황, 전란, 난각 |
| 아황산류 | 아황산, 메타중아황산, 이산화황, 무수아황산 |

### 오탐 제외

한글은 단어 경계가 없어 단순 `in` 검사가 위험하다.

- "땅콩" → **땅콩호박**에 오탐
- "게" → **게르마늄**, 당**게**에 오탐
- "잣" → **잣나무**에 오탐

제외어 목록 우선 필터 + 앞뒤 1글자 검사를 조합한다.

### 복합원재료

`혼합제제`, `식품첨가물혼합제제`, `혼합분유`, `○○시즈닝`처럼 하위 성분이 펼쳐지지 않는 원재료가 실제 데이터에 존재한다. 이 경우 **판정 불가 성분 포함**으로 별도 표시.

### 판정 3단계

| 단계 | 조건 |
| --- | --- |
| 위험 | 등록 알레르겐이 원재료명에 직접 매칭 |
| 주의 | 복합원재료 존재 / 원재료 데이터 자체가 없음 |
| 안전 | 매칭 없음 + 복합원재료 없음 |

결과 화면에는 항상 "본 결과는 공공데이터 기반 참고용이며 실제 제품 포장의 알레르기 표시를 반드시 확인하세요" 고지를 노출한다.

## 6. 추진배경 요지

제도는 이미 존재한다(19개 항목 별도 표시란 의무화). 그럼에도 남는 간극:

1. **표시 대상이 19개 항목에 한정** — 아몬드(즉시형 10위), 키위(12위), 사과(14위), 캐슈넛(20위)이 제외
2. **표시 활용률 저조** — 증상 경험 학생 학부모 중 42.1%만 확인. 불만족 2011년 73.1% → 2015년 개선 후에도 67.9%
3. **누락·사각지대** — 미표시 회수가 2026년 현재까지 반복. 알레르기 유해사례의 70% 이상이 외식 등 비포장식품에서 발생

유병률: 소아·청소년 4~8%, 성인 1~2%

### 왜 OCR이 아닌가 (예상 질문)

OCR은 인쇄된 것만 읽으므로, 표시가 누락된 제품에서는 "알레르겐 없음"이라고 답한다. 품목제조보고는 제조사가 행정기관에 신고한 원재료 원문이므로 포장 표시가 빠져도 데이터에 남아 있을 수 있다. 즉 이 서비스는 포장 표시를 **대체**하는 게 아니라 **교차 검증**한다.

## 7. MVP 스택

- 프론트: React 18 + TypeScript + Vite, `@zxing/library` 바코드 스캔
- 백엔드: Python 3.11 + FastAPI + SQLAlchemy
- DB: SQLite
- 화면: 스캔 / 결과 / 프로필 / 이력
